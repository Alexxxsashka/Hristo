## ВСТУП
Сьогодні розвиток глобальної мережі Інтернет та перехід споживчих звичок у цифровий простір докорінно змінили підходи до роздрібної торгівлі. Спеціалізовані ринки, зокрема ринок тактичного спорядження та страйкбольного обладнання, мають високий поріг входу для споживача через технічну складність продукції. Страйкбольна зброя (приводи) складається з десятків взаємозамінних компонентів, сумісність яких часто є неочевидною для новачка.

**Актуальність теми** зумовлена необхідністю створення інноваційного інтерфейсу, який би дозволяв покупцеві не просто переглядати статичні зображення, а інтерактивно взаємодіяти з продуктом у тривимірному просторі. Існуючі платформи електронної комерції (CMS) загального призначення часто не володіють необхідною гнучкістю для реалізації складних конфігураторів зброї в реальному часі та автоматизації специфічних для ніші бізнес-процесів, таких як управління тисячами комбінацій атрибутів товарів.

**Об’єктом дослідження** є процес продажу та управління запасами спеціалізованого тактичного спорядження.
**Предметом дослідження** є методи та програмні засоби створення інтерактивної Full-stack системи електронної комерції з використанням 3D-технологій та систем аналітики.

## РОЗДІЛ 1. ДОСЛІДЖЕННЯ ПРЕДМЕТНОЇ ОБЛАСТІ ТА ПОСТАНОВКА ЗАДАЧІ

### 1.1. Загальна характеристика об’єкта дослідження Hristo Airsoft
Hristo Airsoft — це сучасне підприємство, що спеціалізується на постачанні високоякісного страйкбольного обладнання. Компанія працює в сегменті B2C та пропонує широкий асортимент: від базових моделей електропневматичної зброї до професійних тюнінг-комплектів. Місія компанії полягає у забезпеченні гравців надійним спорядженням, що відповідає їхнім індивідуальним тактичним завданням.

### 1.2. Організаційна структура підприємства
Управління підприємством здійснюється за лінійно-функціональною структурою. Основні підрозділи включають:
1. **Відділ продажів**: Обробка замовлень, консультація клієнтів.
2. **Складський підрозділ**: Прийом товару, облік залишків, підготовка до відправки.
3. **Технічний відділ (Майстерня)**: Кастомізація зброї під потреби замовника.
4. **Маркетинговий відділ**: Просування бренду та аналіз ринку.

### 1.3. Аналіз нинішнього стану комп’ютеризації
На даний момент автоматизація в установі має фрагментарний характер. Для ведення обліку використовуються таблиці Excel, що призводить до дублювання даних та помилок при великій кількості замовлень. Взаємодія з клієнтами відбувається переважно через месенджери, що унеможливлює збір системної аналітики.
**Висновки щодо незадовільного стану:**
- Високий ризик людського фактора при ручному введенні даних.
- Складність масштабування асортименту через відсутність автоматизованої системи SKU.
- Відсутність єдиної точки правди для клієнта (різниця між залишками в Excel та фактом на складі).

### 1.4. Функціональне моделювання процесів
#### 1.4.1. Модель AS-IS (Як є)
За поточної схеми клієнт змушений уточнювати наявність кожної деталі тюнінгу окремо. Менеджер вручну перевіряє сумісність у прайс-листах, що займає до 30-40 хвилин на одне складне замовлення.

| Підрозділ | Отримує | Передає |
|-----------|---------|---------|
| Продажі   | Запит клієнта | Рахунок, опис збірки |
| Склад     | Накладна | Факт наявності |

#### 1.4.3. Модель TO-BE (Як має бути)
Нова система переносить експертизу сумісності в програмний код. Клієнт сам конфігурує товар у 3D, система автоматично перевіряє залишки та формує фінальну ціну. Менеджер отримує вже готове, оплачене замовлення.

## РОЗДІЛ 2. ТЕХНІЧНЕ ЗАВДАННЯ НА ПРОЄКТУВАННЯ

### 2.1. Постановка задачі
Необхідно розробити інформаційну систему з архітектурою Single Page Application (SPA), що інтегрує хмарну базу даних PostgreSQL та 3D-движок на стороні клієнта.

### 2.2. Функціональні вимоги
1. **Модуль конфігуратора**: Можливість накладання до 5 шарів аксесуарів на одну 3D-модель.
2. **Модуль ERP**: Контроль критичних залишків (якщо менше 5 одиниць — сповіщення).
3. **Модуль BI**: Генерація графіків доходу за довільний період.
4. **Синхронізація**: Миттєве оновлення кошика між вкладками (Cross-tab sync).

## РОЗДІЛ 3. ПРОЄКТУВАННЯ ТА РЕАЛІЗАЦІЯ

### 3.1. Обґрунтування вибору технологій
Для реалізації проєкту обрано стек **React 19 + Node.js + PostgreSQL**.
- **React 19**: Дозволяє використовувати "Actions" для обробки форм без зайвого коду та забезпечує миттєвий відгук інтерфейсу.
- **Three.js**: Єдиний стандарт для браузерної 3D-графіки, що підтримує апаратне прискорення GPU.
- **Zustand**: Мінімалістичний менеджер стану, який у 4 рази легший за Redux, що важливо для швидкого завантаження на мобільних пристроях.

### 3.2. Проєктування бази даних
База даних реалізована у PostgreSQL (Neon). Використано третю нормальну форму для мінімізації надмірності.
**Основні сутності:**
- `Products`: Загальна інформація.
- `Variants`: Конкретні SKU (комбінації кольору/розміру).
- `Attributes`: Характеристики (Калібр, Матеріал, Вага).

### 3.3. Реалізація функцій системи
#### 3D-конфігуратор
Використовується патерн декларативного управління сценою. GLB-моделі завантажуються асинхронно через `Suspense`. Кожен аксесуар є окремим дочірнім компонентом, який рендериться лише за умови наявності відповідного прапорця у стані Zustand.

#### Бізнес-аналітика
Реалізована через складні SQL-запити з групуванням. Наприклад, запит для аналізу продажів за місяць:
```sql
SELECT DATE_TRUNC('month', created_at) as period, SUM(total_price) 
FROM orders 
GROUP BY period;
```

### 3.4. Інструкція користувача
1. **Авторизація**: Вхід через Google або Email.
2. **Каталог**: Використання фільтрів ліворуч для звуження пошуку.
3. **Конфігурація**: Натискання на іконку "3D" відкриває інтерактивне вікно.
4. **Оплата**: Введення даних карти у захищеному фреймі Stripe.

### 3.5. Тестування
Проведено тестування на базі 20 тест-кейсів.
**Результати:**
- **Валідація форм**: Zod успішно відхиляє некоректні дані у 100% випадків.
- **Синхронізація**: BroadcastChannel оновлює кошик у сусідній вкладці за <10 мс.
- **Мобільна адаптивність**: Перевірено на iPhone 13 та Pixel 6 — інтерфейс адаптується без втрати функціоналу.

## ВИСНОВКИ
В ході виконання кваліфікаційної роботи було спроектовано та впроваджено спеціалізовану систему електронної комерції для магазину Hristo Airsoft. В результаті розробки:

Розроблена система готова до промислової експлуатації та має високий потенціал для масштабування на інші ринки технічно складних товарів.
