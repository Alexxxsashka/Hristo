Отчетность для ЛР№7

1. Где главный файл всех подключений:
Главный файл всех подключений - server.ts. В этом файле происходит инициализация Express сервера, подключение к Firebase Admin SDK, настройка базы данных (PostgreSQL с fallback на PGLite), инициализация Stripe для платежей, настройка multer для загрузки файлов и Vercel Blob для хранения. Также здесь определяются middleware и базовые настройки для API.

2. Где происходит подключение к БД:
Подключение к базе данных происходит в server.ts и api/index.ts. В server.ts создается pool для PostgreSQL с использованием переменных окружения (DATABASE_URL и т.д.), с fallback на локальную PGLite базу данных. Также инициализируется Firestore через Firebase Admin SDK для NoSQL данных. В api/index.ts аналогично создается pool для подключения к PostgreSQL на Vercel.

3. Где происходит синхронизация данных:
Синхронизация данных происходит в Zustand stores, таких как shopStore.ts, configuratorStore.ts и других. Например, в shopStore.ts функция fetchProducts загружает продукты из Firebase через firebaseService. Аналогично, другие stores синхронизируют категории, заказы и т.д. с помощью сервисов, которые взаимодействуют с Firebase Firestore и PostgreSQL.

4. Где происходит взаимодействие формы добавления / редактирования / удаления и передачи данных на Vercel:
Взаимодействие форм происходит в компонентах админ-панели, таких как ProductForm.tsx, CategoryManager.tsx и т.д. Эти формы используют firebaseService для выполнения CRUD операций (создание, обновление, удаление). Данные передаются на Vercel через API endpoints, определенные в api/index.ts, который является Vercel serverless функцией. Например, ProductForm вызывает методы firebaseService для сохранения продукта, а сервис отправляет запросы к API на Vercel для обработки и сохранения в базе данных.
